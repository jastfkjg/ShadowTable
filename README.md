原生微信小程序 + 单体 Node.js HTTP 服务 + SQLite。线下讨论，线上管理身份、行动和结算。房主也是普通玩家，服务器使用统一的按玩家过滤视图，房主没有全员身份或秘密行动管理端。

## 当前实现范围

小程序默认按需操作：创建房间→加入/选座→准备→房主发放身份→按线下进度自由使用工具→房主结束→同房再开。

发牌后房主可任意选择「投票」「做任务」「刀梅林」，逆仆局另有「刀逆仆」。投票可以不选队伍；任务自行选择队员和1/2张失败票门槛，仅队员提交；刺客在自己的手机上选刀人目标，其他玩家只需确认；所有人显示相同的完成状态，避免进度暴露刺客身份。8人局和线下辅助板继续在线下刀人。每次结算只记录该操作，不因三次成功/失败、连续否决或刀人结果自动结束本局。切换未结算操作前须确认作废，玩家身份和已结算记录保留。已发牌的旧房间也可直接使用新工具，无需重发身份。

## 本地运行

需要 Node.js >=22.13（内置 `node:sqlite`，当前22.x会提示实验性API）。无第三方服务端运行依赖；开发测试使用锁定版本的模板编译器和格式化工具。

```sh
npm ci
npm test
npm run check
npm run dev
```

服务默认 `http://127.0.0.1:8787`，数据在 `data/shadowtable.sqlite`。`npm run dev` 开启仅用于联调的匿名开发登录，每次新登录生成独立身份，不接受客户端指定用户ID。会话在设备上保存；清掉开发会话无法恢复原开发身份。正常微信登录按 OpenID 恢复同一用户。

1. 微信开发者工具导入项目根目录（读取 `project.config.json`）。`touristappid` 仅作为导入占位，上线前替换真实小程序 AppID。
2. 本地测试将 `miniprogram/config.js` 的 `devAuth` 设为 `true`；服务运行 `npm run dev`。开发者工具本地设置关闭 request 域名校验，才能使用 localhost HTTP。
3. 首页「我的牌桌」列出当前微信身份已经加入的房间；可恢复原座位。房间内「我的牌桌 / 切换房间」只切换界面，不退出对局。打开朋友的新邀请优先保留邀请房间码，不强制回到之前的房间。
4. 使用独立模拟器存储/独立微信设备登录各玩家。创建6人房，其他玩家输入6位房间码加入。点击空位换座，全部准备后房主开始。
5. 每人主动打开私密面板并确认；房主推进到队长组队。队长点选指定人数后提交；房主开启组队表决。所有人秘密提交后房主结算，再开启任务。非队员也在统一私密面板确认等待。重复任务至结局；最终阶段非刺客也需确认，刺客选择目标。
6. 11人局三成功后，先填逆仆目标再填梅林目标；刺客在自己的私密面板录入线下决议，其他人统一确认。逆仆是否转阵营、个人输赢仅在其私密卡显示。影中执刃辅助模式在线下结束特殊结算后，由房主点击结束，再同房重开。
7. 断线重连点「重试」，网络不确定时保留原请求编号。不得用不同请求替代尚未确认的请求。应用切后台遮盖身份，返回不自动揭示。

真机不能用手机的 `127.0.0.1` 访问电脑服务。开发阶段可在同网使用电脑地址并设置 `HOST=0.0.0.0`，仅在工具允许的调试环境使用；正式真机链路使用下述 HTTPS 配置。

## 微信真机与部署

已提供 [GitHub Actions 自动部署说明](docs/deployment.md)：推送 main 后先测试并构建镜像，再通过 SSH 更新独立 Compose；健康检查失败回退应用镜像。公网入口由 jastcraft-infra 独立 Caddy 网关管理。首次使用需初始化服务器并配置部署 Secrets。

本仓库未包含用户的小程序 AppID、AppSecret、已备案域名或微信发布授权；未冒充已发布或已通过真机验收。

- 将真实 AppID 写入 `project.config.json`；将微信配置只注入服务端 `WECHAT_APP_ID` / `WECHAT_APP_SECRET`。客户端 `devAuth:false`。
- 单台服务器运行 Node 服务（`NODE_ENV=production`，`DEV_AUTH=0`），反向代理提供 HTTPS，禁止公网访问 SQLite 文件或仓库目录，代理只转发 API。将 HTTPS 域名添加到微信后台的 request 合法域名，并修改 `miniprogram/config.js` 的 `baseUrl`。
- `wx.login` 临时 code 发送到 `/api/login`，服务端调用微信 `jscode2session`，只把随机会话令牌返回手机。AppSecret、session_key 和 OpenID 不下发。会话令牌有效30天，可重新微信登录恢复房间。
- SQLite目录仅服务账号可读，备份应使用 SQLite backup 或停服备份整个数据库，不能运行中只复制主文件忽略 WAL。
- 只运行一个 Node 实例；房间变更和请求回执在 `BEGIN IMMEDIATE` 事务里同步提交。无微服务、Redis或消息队列。

生产示例（通过你的部署环境安全注入密钥）：

```sh
NODE_ENV=production DEV_AUTH=0 PORT=8787 npm start
```

## 隐私设计

身份不写小程序存储。公共房间响应没有角色、内部用户ID、行动明细、其他人的提交状态或秘密操作时间戳；私密接口只返回本人角色/初始视野/合法动作。公共组队票按规则在结算后公开，任务牌仅汇总。房主不能强制通过未完成阶段，只能终止本局。终止不判胜负且不新增身份披露。全部玩家断线也不会自动变更胜负。

平台后台截图、旁观实体屏幕无法由代码绝对阻止；应用已在页面及应用的 onHide 清除身份内容，异步身份响应带前后台与代次检查，避免后台旧响应重新揭牌。

## 入口与昵称（2026-09-14 更新）

中文名称统一为「桌边助手」。首页分为创建 / 加入；创建先选6–12人数，再选该人数可用板子，只有一种时自动选择。12人当前可选经典完整角色和影中执刃线下辅助；玩法说明仅按阵营列出当前人数的角色与数量；房间内板子名右侧的「配置说明」可打开角色弹窗。未确认玩法仍禁用。准备、开局按钮位于座位列表上方，房间设置和转交房主按需展开。

桌上昵称使用微信 `input type="nickname"` 填写能力，需要玩家主动选择微信昵称或自行输入，不能静默读取。通过原生表单提交最终值，成功加入或创建后记住该设备上的昵称。模拟器不能替代真机昵称候选与安全检查验收。

首页默认加入房间。「我的牌桌」中当前房主可删除牌桌，需确认；会移除所有成员与房间记录，进行中对局不判胜负。转交房主后删除权限随之转交。离开后刷新列表；失效房间403/404将清除本地入口并停止轮询。

## 离席与空牌桌（2026-09-14）

准备阶段离开仅释放座位，空牌桌保留在SQLite中；只有房主明确删除才移除。当前房主离席仍保有归属，可在「我的牌桌」点击「重新入座」或删除。离席房主不能获取私密视图，需重新入座后管理对局。房主离席时保留一个入座名额，其他玩家不能自动接管房主；需要时由房主入座后主动转交。进行中仍不可离席，需要先结束对局并回到准备阶段。此前已删除的房间不能由本次修改恢复。

## 本地陪测控制面板

运行 `npm run dev`，浏览器打开 `http://127.0.0.1:8787/dev`（与小程序使用同一开发服务）。小程序仍以你自己的开发身份操作；控制面板只创建和操作独立陪测账号。

1. 在小程序建房，复制房间号。
2. 面板输入房间号，点击「添加测试玩家」，再点「补齐空位」。
3. 点「全部准备」，你在小程序也准备，然后由房主开局。
4. 在面板「全部确认」完成测试账号的身份确认，你在小程序完成自己的确认，再推进。
5. 测试玩家当队长时在对应卡片勾选队伍；投票可逐人选择或批量赞成/反对；任务可逐人出牌，或批量合法成功/失败。非队员点「全部确认」。批量操作不会替真人提交。
6. 刺客进入最终目标阶段时，在其卡片选择目标并确认。11人依次支持逆仆指认和梅林刺杀。当前没有守护/十二骑士等未实现技能，影中执刃辅助版的特殊结算仍在线下处理。
7. 可勾选「显示测试玩家身份」查看这些账号各自的角色和视野；默认隐藏。暂不提交某名玩家即可测试阶段未完成提示。
8. 网络结果不确定时，点击对应玩家的「重试未确认操作」。同一标签页刷新保留开发会话及原请求编号；新标签页/关闭标签页后不保证恢复。不要清除浏览器会话存储来解决未确认提交。
9. 点击「清空陪测玩家」释放测试座位，再添加玩家即可重新测试，也可输入另一个房间号。若陪测玩家担任房主，会先终止进行中的对局、同房重开，再将房主转交给仍在座的真人玩家；没有真人在座时会提示先入座。真人担任房主时，需先在小程序结束本局并同房重开。真实玩家和牌桌保留；网络异常时保留未确认请求，重试确认后可继续清空。

隔离方式：只有 `DEV_AUTH=1` 与 `DEV_PANEL=1` 同时启用且非production时才加载面板；`npm run dev`自动设置这两个开关。`npm start`默认不启用；production模式即使误传开关也不能访问。面板页面、JS、CSS、图标均校验loopback地址、Host与Origin，只允许本机访问，未增加读取全房秘密或代操作真实玩家的接口。面板文件位于server目录，不进入miniprogram发布包。正式环境使用 `NODE_ENV=production DEV_AUTH=0 DEV_PANEL=0 npm start`。

房主可查看当前线上操作的完成进度（已完成、未完成、无需操作），接口不提供具体票型或刀人目标；普通玩家不获取他人进度。身份默认折叠为一行入口，点击展开；结束本局按钮位于公开记录之后的页面底部。

玩家需要投票、出任务牌或刀人／确认时，操作以独立弹窗自动展示，不再放入身份卡。每个阶段自动提示一次，关闭后可从「待完成操作」重新打开；提交后关闭，切后台及阶段变化会清除弹窗私密内容。
