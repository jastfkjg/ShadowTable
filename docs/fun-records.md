# 趣味记录与荣誉榜

实现范围：小程序与网页版的个人页入口、战绩页趣味分组、按指标回查对局、每局事件、结束页本人记录、独立于计分开关的结果登记、趣味次数与比例榜、管理员更正和可靠的旧数据回填。无新增底部导航，不部署。

称号在小程序、网页版、个人趣味战绩、排行榜、月度战报和分享图片中共用同一份定义：

| 称号 | 统计口径 |
| --- | --- |
| 最强派西 | 初始派西身份，三蓝后仍有梅林在场且最终刀未刺中梅林的局数 |
| 竭尽全力 | 初始派西身份，三红或最终刀刺中梅林的局数，一局最多一次；提前盘刀刺中也计入 |
| 闪身步大神 | 梅林成功躲过最终刀的次数 |
| 舍我其谁 | 梅林被最终刀刺中的次数 |
| 职业刺客 | 刺客非空最终刀刺中梅林的次数 |
| 背锅侠 | 刺客非空最终刀刺错梅林的次数 |
| 绝对防御 | 守卫、魔术师实际保护友方阵营的次数 |
| 卧龙凤雏 | 守卫、魔术师实际保护对方阵营的次数 |
| 职业杀手 | 有击杀技能的玩家通过轮内刀、枪、决斗让对方阵营实际出局的次数 |
| 痛击队友 | 有击杀技能的玩家通过轮内刀、枪、决斗让友方阵营实际出局的次数 |

守卫必须实际挡下伤害，魔术师必须通过换号让原本会受到伤害的目标避开伤害；仅选择目标或换号被触发不算保护。一次换号避开多次攻击可记多次保护，按每次实际保护计数。原目标本来不受攻击影响时不计保护。防御比例分母为实际保护总次数，分别显示保护友方的成功率和保护对方的发生率。

击杀按技能开始时的角色、当前阵营与换号／替死后的实际承受者计算，合并刀、枪、决斗，分母为对应轮内出手总次数。缴械、守护挡下、反伤、决斗失败、已出局和不受此刀影响不计击杀；最终刺杀由梅林、刺客称号单独统计。原有刀、枪、决斗与终局挡刀细项保留为个人过程明细与旧接口兼容，不再作为独立称号公开排行。未使用、作废和未提交不算失败。空刀不并入刺客命中比例；梅林面对空刀仍可记躲刀，派西三蓝后梅林已全部出局不计保护成功。

数据：结构化事件只在完整技能环节结束后提交；未完成环节取消不留有效次数。结束归档、个人投影及幂等回执保持同事务。数据只有正式结束后可从本人接口读取，公共榜不返回事件、目标、牌桌和内部身份。未知／零／不适用分开；关闭计分仍记录趣味。测试房间及有陪测参与的有效对局中，真实玩家和开发账号正常记录与展示趣味数据，开发账号可参与趣味榜单，公开状态遵循本人展示开关；陪测账号不保存个人趣味投影或统计，不参与公共排行榜。混合对局保留结算所需的共同事件事实，以计算真实玩家的趣味结果。旧测试局仅因测试标记被排除的趣味记录会在启动时根据已保存事实恢复；没有操作依据的指标继续显示未知。

指标选择按“全部／好人／坏人／其他”分类，分类按适用身份：派西、梅林及守卫／魔术师的两项防御称号归好人，刺客称号归坏人，跨阵营击杀称号归其他。所有十项始终保留入口，不因缺少记录而隐藏。选项以称号为主标题，身份标签和达成条件辅助说明；列表显示总项数，并在尚未滚到底时提示“下滑查看更多”。排行榜、个人趣味战绩、月报和分享图共用身份文案，击杀类完整适用身份在规则及身份筛选中展开。

排行：公开十项称号的次数及比例榜，正向五项显示“成功率”，其余五项显示“发生率”。跨玩法汇总，不提供板子选择；防御称号可筛选守卫、魔术师，击杀称号可筛选各类击杀角色。比例榜有有效机会即可参与，不设累计对局或出手次数门槛。次数相同并列；原始比例相同以机会数较多优先，两者相同并列跳号。全部／本月使用北京时间。保留本人样本，沿用分页版本和缓存失效。个人详情仍保留玩法分组，便于回看现场规则。

投影版本为 `fun-2026-10-v3`，启动时从已保存事实重新计算所有历史投影并同步结束牌桌。旧攻击事实可恢复实际击杀；防御仅从完整复盘中的防御角色、触发状态、目标与换号路径恢复，没有完整过程时保持未知，不能把终局挡刀推断为防御技能保护。

验收必须覆盖：三绿／三炸／提前／否决的区别；积分关闭；实际刺杀和空刀；初始与当前身份；转阵营、换号、替死、守护、反伤、互刀和抽B；不使用、作废、回滚、重试；隐私；旧数据未知和可靠回填；管理员更正与重启；榜单阈值、并列、过滤、月界、隐藏、分页及迟到响应；两端操作流程；小屏、横屏、字号放大、减少动态效果、模板编译及完整回归。

## 页面与布局

“我的”提供独立趣味入口；“我的战绩”在同一页面保留“统计／对局记录／趣味记录”三个页签及各自滚动、筛选和折叠状态。统计页突出总胜率，阵营与角色使用共用背景的折叠列表，积分独立展示。趣味页在各玩法内按终局表现与轮内技能分组；单指标把成功次数与机会数合并为一行，详细数据范围集中到统计口径说明。卡片减少留白，分享及回查入口保留至少 44px 点击范围，底部滚动内容避开系统手势区。完整分享入口位于统计和趣味页的内容顶部，单项趣味分享仍保留。

对局记录按日期分组，胜负标签与角色、阵营、人数分层展示。时间、板子、角色、胜负筛选放在底部弹层；选择与重置只修改草稿，点击“查看对局”才一起应用，关闭弹层放弃草稿。全部记录加载完成后才展示胜负汇总，避免把分页中的局数当作总数。

趣味按玩法与角色分组，全部卡片直接展示，不设收起或展开更多记录按钮：派西、梅林和刺客为两列数字，轮内攻击为敌方／友方／未生效三列。次数、实际机会和比例集中展示，不使用进度色条；已记录与未知局数在展开说明中查看。单指标将成功率放在次数旁，零机会或未知数据不展示成功率。按出刀角色展开后仍可回查相关对局。未知显示“—”，有记录的零显示“0”。

“刺客”仅统计刺客本人的非空最终刺杀。趣味记录与完整分享中移除“最终带刀”卡片，个人页摘要从其余卡片中选择亮点；最终刀事件继续作为结算与对局回查依据保留。

每局折叠行显示本人亮点，展开显示初始身份和本人技能／最终刀故事，然后显示同桌成员。结束页也提供本人趣味摘要和统计入口。两端表单复用“登记本局结果”：可计分时提交计分原因，关闭计分时提交趣味原因；最终刀有在场刺客时自动记录刺客，只有场上没有刺客时才选择实际在场带刀人，自刀目标禁选。信息不足可仅登记胜方，相关终局记录保留未知。

排行榜采用积分／局数／胜率／趣味四页签；趣味页依次显示指标选择、次数／比例和出刀角色、榜单，不显示板子按钮。小程序以两列展示展开后的指标选项，网页版沿用可展开的横向指标栏。本人名次、数值、样本与公开开关固定在底部，横屏转为页面内布局。未达到成功率门槛仍显示本人比例和还差多少次机会。

## 指标和分母

派西维尔、刀客刀法和骑士的文案定义由 `miniprogram/fun-copy.js` 在小程序、网页版和服务端共用。展示层按指标 ID 和事件技能类型转换旧接口或历史快照中的文案，覆盖摘要、详情、比例说明、排名、结束页和分享。挡刀事件只展示本人座位；资格判断与分母仍沿用原规则。转换仅生成显示副本，不改写历史事实或次数。

| 指标 | 本人记录 | 公共榜 | 比例分母 |
| --- | --- | --- | --- |
| 派西维尔 | 三绿车、三炸车 | 三绿车、三炸车 | 有明确终局原因的初始派西对局 |
| 梅林 | 躲刀、中刀 | 成功躲刀、被刺 | 在场梅林实际面对的最终刺杀（含对方空刀） |
| 好人 | 成功挡刀次数、成功率 | 成功挡刀 | 终局时作为在场非梅林好人、面对有明确目标的最终非空刀的局数 |
| 刺客 | 刺中梅林、歪刀 | 刺中梅林、歪刀 | 本人实际最终刺杀，排除空刀 |
| 刀客刀法 | 刀中敌方、刀中友方、未生效；选敌率 | 刀中敌方、刀中友方 | 本人已完整结算的轮内刀 |
| 猎人枪法 | 命中敌方、命中同伴、未生效；选敌率 | 命中敌方 | 本人已完整结算的枪击 |
| 骑士 | 决斗敌方、决斗友方、未生效；选敌率 | 决斗敌方、决斗友方 | 本人已完整结算的决斗 |

十二骑士允许身份变化，多梅林场景按实际被刺座位记录中刀，其他在场梅林可记录个人躲刀；个人躲刀与阵营胜负分开。反伤使攻击者出局时，该次出手记未生效；女巫替死按直接承受者阵营归属。选中敌方但被守护挡下，选敌率可成功，敌方有效命中率失败。同局多次完整技能会逐次记录，派西三绿／三炸一局最多一次。原始事件仅用于服务端回溯；公开排行榜只有指标和样本。

挡刀仅统计最终刀落在本人且本人为非梅林好人的情况，一局最多一次。以最终身份、当前阵营与存活状态判断，不沿用开局阵营；梅林、坏人和已出局玩家不形成挡刀机会。刀落到其他人（含梅林、坏人）是本人的一次未挡刀机会；空刀、三炸和五次否决不形成机会。只登记胜方的旧对局显示未知；已保存明确刀口的旧记录随 `fun-2026-10-v2` 投影升级自动补算，管理员改刀口同步重算，不变更积分规则。

新增五项榜单直接读取已有趣味投影，无须迁移或重建对局。未知不当作零；友方命中按技能发生时的当前阵营及换号／替死后的实际承受者统计，未生效不算误伤。公开资格与正向含义分别保存，个人统计中的反向颜色、正向摘要及比例条不随开放榜单改变。

维护与迁移详见 [架构与接口](architecture.md)。测试使用独立内存或临时SQLite数据库，浏览器截图保存在 `output/playwright/fun-*.png`。微信真机与正式部署仍需按项目发布流程验收。

登记入口统一将提前盘刀计入“三绿”，不再单列提前盘刀或五次否决。历史原因及旧客户端提交保持兼容，不重写既有记录。

## 玩家票选 MVP / SVP

确认有效胜负后，当前房主可选择发起一次最佳玩家票选；本局参赛者（含已出局者）匿名投票，旁观者不参与。测试房间的陪测账号也可投票及获奖，按归档时的最终阵营划分胜败候选人；陪测台支持逐人选择 MVP / SVP、修改选票，陪测担任房主时可发起或截止票选。MVP 只能选胜方，SVP 只能选败方，均不能投自己。两项一起提交；某项无可选对象（例如唯一胜方就是自己）时自动跳过。关闭弹窗保留牌桌入口，截止前可修改，未投玩家回到牌桌后补提示。

投票默认 2 分钟，全员提交时自动结算。房主可以提前截止；同房重开或解散也会先结算已有选票。至少一半参赛者完成可投项目才颁奖（向上取整），不足时显示未达人数；每项最高票获奖，同票全部并列。最终结果对所有牌桌成员展示获奖头像、名称、本局号码及所获票数；对局详情保留同样结果。每项无有效选票则不颁发该奖。

趣味记录新增跨玩法「玩家票选 / 本场最佳」，分别累计最强 MVP、最强 SVP 获奖局数，每局每项最多 +1，票数不累计。点击次数回查获奖对局。两个趣味榜沿用全部 / 本月（按对局结束时间与北京时间）、公开开关与次数并列，不提供比例榜或身份筛选，不改变积分。月度战报的既有十项技能称号保持原范围。

陪测账号的获奖仅显示在本局结果中，不生成个人对局、趣味记录或排行榜数据；真人在测试房间获奖仍按原规则累计。纯陪测对局不建立个人归档，由房间与私有票选保存必要的本局上下文，支持服务重启后继续投票和截止结算。

两端最终结果和对局详情中的已结算荣誉采用紧凑双栏：MVP / SVP 并排，头像旁显示昵称，下一行合并号码与票数；并列玩家在对应栏逐个排列，长昵称自然换行，不截断获奖名单。标题与参与人数合并为一行，避免占据过多结算卡片空间。

`honor_polls` 按对局编号持久化选民快照、截止时间及私有选票，与对局公共快照分开。发起、投票与截止沿用幂等回执和事务；公共接口仅返回进度及本人选票，结算后只发布获奖名单与票数。截止扫描支持重启恢复；获奖事实写入归档后重建趣味投影，不能因重复结算、重开或服务重启累加。作废 / 删除对局同步排除统计和榜单；更正胜方使原票选失效。旧局未发起票选时不推断荣誉。

验证：`tests/honors.test.js` 覆盖投票资格、自投及跨胜负拦截、修改、匿名、平票、人数门槛、超时、唯一胜方、持久化、归档、管理员更正、排行、HTTP 幂等与旧局重试，以及真人 / 陪测混合与纯陪测投票的统计隔离。`tests/admin.test.js` 验证管理陪测实际投票接口与权限；`tests/companion-ui.test.js` 验证陪测台的选票、草稿、提交与并列展示；两端控制器和小程序模板有交互及卡片测试。`scripts/render-honors-preview.js` 从实际 WXML / WXSS 生成投票、获奖、趣味记录、榜单与归档详情的视觉检查页面。
