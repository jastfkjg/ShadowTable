# 积分系统

积分从功能启用后新开的对局开始记录。第一版适用于经典基础 5–8 人，以及经典基础 10、12 人；9、11 人逆仆与扩展板暂不计积分。开发、陪测、测试房间、终止局和缺少计分依据的局不计积分。积分资格独立于既有胜率统计，0 分的有效计分局参与积分场均与连胜计算。

## 默认分值

| 结果 | 普通好人 | 梅林／派西 | 坏人 |
| --- | ---: | ---: | ---: |
| 三绿、刺中梅林 | 1 | 1 | 3 |
| 三绿、未刺中梅林 | 2 | 3 | 0 |
| 三次任务失败／连续五次否决 | 0 | 0 | 3 |

好人获胜时，最终被刺中的非梅林好人额外 +2。派西挡刀共 5 分；空刀或刺到坏人不发挡刀奖励。连胜默认只展示，得分不改变个人胜负判断。

## 只部署服务端修改规则

规则唯一配置入口为 `server/scoring-rules.json`。修改后部署并重启服务端即可，无需再次发布小程序或修改网页版：

- `awards`：每项的分值、名称与条件。条件支持 `faction`、`outcome`、`roleId`、`reason`、`isTarget`，数组值表示匹配任意一项，所有条件之间为“且”。符合条件的项目累加；0 分项目不写入明细。支持 -100 到 100 的整数分值，客户端按正负号展示。
- `boards`、`excludedIdentityPrefixes`：计分板子／人数与排除的账号前缀。扩展板应先确认其胜负及身份变化逻辑，不能仅扩大板子名单后套用经典规则。
- `endReasons`：结算选项及名称。`requiresTarget: true` 使用已有座位／空刀选择器，最终根据梅林身份确定胜方；其余选项由 `winner` 指定胜方。
- `streakBonus`：默认 `enabled: false`。开启后，在一段连胜首次达到 `threshold` 时追加 `points` 分，使用 `label` 展示。失利清零；排除局不推进也不打断。
- 修改规则时更新 `version`，便于识别不同批次。服务端也保存配置内容指纹，忘记修改版本号不会影响旧局的规则快照。

每局开局时冻结完整规则。进行中的局继续使用原规则，历史得分及明细不会因配置更新而改写。客户端没有内置分值表、角色奖励表或固定加分项目；帮助页说明由服务端根据规则生成。如果将来增加需要玩家录入的新种类信息，仍可能需要升级客户端；仅修改计分逻辑、分值、奖励名称、已有条件或连胜参数只需部署服务端。

首次上线此功能需要发布一次新小程序版本，以加入结算输入和积分页面。先部署服务端兼容旧客户端：旧客户端只登记胜方时仍归档战绩，但因缺少计分依据不计积分。

新版客户端连接尚未更新的旧服务时，积分榜参数可能被拒绝。客户端会自动读取局数榜、禁用积分入口并提示未开放；局数、胜率和周期切换继续可用。新服务的榜单响应提供 `availableMetrics`，后续刷新可自动恢复积分入口，不需再次发布客户端。其他鉴权、网络及服务错误仍按原错误处理。

## 数据与接口

- `matches.snapshot`：计分规则快照、结束事实、计分资格和结果更正版本。
- `match_players.snapshot`：本人得分及各项明细。内部角色 ID 仅供服务端更正计算，个人明细接口不返回同桌身份。
- `match_scores`：每局每人一条，主键 `(match_id, uid)`；保存资格、分数、时间与明细。积分与战绩、房间保存、请求回执处于同一事务。重复提交不重复计分。
- `GET /api/scoring/rules`：公开的当前规则说明，不包含玩家信息。
- `GET /api/me/stats`：新增 `score`，包括总分、本月积分、计分局数、场均分、当前／最高连胜；阵营和角色分组附带积分统计。
- `GET /api/me/matches?offset=0&scored=1`：仅筛选计分局，包含 0 分局；不加筛选时显示完整历史。旧记录标记 `legacy`，排除局标记 `excluded`。
- `GET /api/leaderboard?metric=points&period=month`：积分榜；至少一场计分局即可参加，同分并列。公开资格、分页版本、本人排名、公开开关与原榜单一致。本月按北京时间结束时间取半开区间。

房主结束本局时提交服务端提供的 `scoreReason`；刺杀型原因必须提供 `scoreTarget`（座位或 0 表示空刀）。服务端在结束操作中计算胜方与分数，不提供按座位查询身份或计分预览。结束界面只向本人展示其积分。

## 显示位置

“我的”显示总分、本月积分，并链接积分明细与规则；“我的战绩”展示场均、计分局数、连胜以及阵营／角色积分；“对局记录”展示每局分数、展开明细及排除原因；“排行榜”使用积分／局数／胜率三个主指标，胜率下再选择阵营。网页版同步提供上述内容和完整对局记录分页。

## 管理员更正

管理平台可按房间号查找最近 50 场归档对局，选择实际结束原因／目标，并填写更正原因。更正使用本局原规则，同步更新胜负、积分、受影响的后续连胜奖励及仍可见的结束页面。请求编号保证重试幂等，结果版本防止并发覆盖，审计记录保存前后结果与原因。

相关接口为 `GET /api/admin/matches?code=123456` 和 `POST /api/admin/matches/:id/correct`，沿用管理平台鉴权及来源检查。旧局或不在计分范围的局不能补算积分。
