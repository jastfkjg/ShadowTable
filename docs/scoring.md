# 积分系统

积分从功能启用后新开的对局开始记录。适用于经典基础 5–8、10、12 人，以及十二骑士 10、11、12、13 人；9、11 人逆仆与其他扩展板暂不计积分。测试房间及有陪测参与的对局中，真实玩家和开发账号正常计分；陪测账号不保存个人战绩、积分及趣味记录，纯陪测对局不归档；终止局和缺少计分依据的局不计积分。积分资格独立于既有胜率统计，0 分的有效计分局参与积分场均与连胜计算。

房主在准备阶段通过“房间设置 → 积分 → 本局计分”主动开启或关闭，修改后自动保存并让玩家重新准备。新建房间时，10 人及以上默认开启，其他默认关闭；更换人数时重新应用人数默认值，更换同人数的板子保留选择。同桌玩家可看到计分状态。开关在发牌后固定，同一房间重开保留房主选择。开启开关仍须满足板子与人数范围等计分资格；关闭的局正常保存胜负战绩，但不参与积分和连胜统计，管理员不能将其补算为计分局。

兼容旧数据：已开局且保存了积分规则快照的测试／开发对局也可正常提交计分结算，分值与结束原因仍沿用开局快照；旧准备房间按人数默认值展示。已归档历史局不自动补算积分。

## 默认分值

| 结果 | 普通好人 | 梅林／派西 | 坏人 |
| --- | ---: | ---: | ---: |
| 三绿、刺中梅林 | 1 | 1 | 3 |
| 三绿、未刺中梅林 | 2 | 3 | 0 |
| 三次任务失败／连续五次否决 | 0 | 0 | 3 |

好人获胜时，最终被刺中的非梅林好人额外 +2。派西挡刀共 5 分；空刀或刺到坏人不发挡刀奖励。连胜默认只展示，得分不改变个人胜负判断。

十二骑士按结束时的当前身份与最终阵营计分：兰斯洛特转换阵营后随新阵营得分；抽 B 牌后按新身份得分；复活甲保留原身份；永久出局保留最后阵营并参与计分。实际盘刀目标只允许在场玩家或空刀。空刀且场上没有存活梅林时坏人胜；仍有存活梅林时好人胜。提前盘刀按三绿盘刀计分，同样沿用上表；好人失利时全员各领取三绿阶段 +1，坏人各 +3；好人获胜时领取基础、角色及挡刀奖励。未完成技能被明确作废后结束时，先还原技能前状态再结算。

十二骑士新增支持从新版规则发牌的对局生效。已开局或历史局保留原规则，之前被排除的十二骑士局不补算。

计分板子范围、提前盘刀选项及分值通过服务端下发，已支持积分通用表单的客户端无需新增板子专用表单。本次客户端同时优化了在场目标筛选；旧版表单若仍列出已出局座位，服务端会拒绝该目标，选择在场玩家或空刀仍可正常结算。

## 只部署服务端修改规则

规则唯一配置入口为 `server/scoring-rules.json`。修改后部署并重启服务端即可，无需再次发布小程序或修改网页版：

- `awards`：每项的分值、名称与条件。条件支持 `faction`、`outcome`、`roleId`、`reason`、`isTarget`，数组值表示匹配任意一项，所有条件之间为“且”。符合条件的项目累加；0 分项目不写入明细。支持 -100 到 100 的整数分值，客户端按正负号展示。
- `defaultEnabledMinPlayers`：当前为 `10`，控制新房间和更换人数后的计分开关默认值。阈值及说明由服务端下发，后续调整只需更新服务端。
- `boards`：计分板子与人数范围。测试标记和账号前缀不影响计分资格。其他扩展板应先确认其胜负及身份变化逻辑，不能仅扩大板子名单后套用经典规则。
- `endReasons`：结算选项及名称。可选 `boards` 限定该原因适用的板子（如提前盘刀仅用于十二骑士）。`requiresTarget: true` 使用已有座位／空刀选择器，最终根据梅林身份确定胜方；其余选项由 `winner` 指定胜方。
- `targetModes`：十二骑士使用 `living_merlin` 判定在场梅林与空刀，经典板缺省保持原判定。该配置随开局规则冻结，管理员更正复用同一判定和归档的存活状态。
- `notes`：补充说明，由服务端下发到积分规则页。
- `streakBonus`：默认 `enabled: false`。开启后，在一段连胜首次达到 `threshold` 时追加 `points` 分，使用 `label` 展示。失利清零；排除局不推进也不打断。
- 修改规则时更新 `version`，便于识别不同批次。服务端也保存配置内容指纹，忘记修改版本号不会影响旧局的规则快照。

每局开局时冻结完整规则。进行中的局继续使用原规则，历史得分及明细不会因配置更新而改写。客户端没有内置分值表、角色奖励表或固定加分项目；帮助页说明由服务端根据规则生成。如果将来增加需要玩家录入的新种类信息，仍可能需要升级客户端；仅修改计分逻辑、分值、奖励名称、已有条件或连胜参数只需部署服务端。

首次上线此功能需要发布一次新小程序版本，以加入结算输入和积分页面。先部署服务端兼容旧客户端：旧客户端只登记胜方时仍归档战绩，但因缺少计分依据不计积分。

新版客户端连接尚未更新的旧服务时，积分榜参数可能被拒绝。客户端会自动读取局数榜、禁用积分入口并提示未开放；局数、胜率和周期切换继续可用。新服务的榜单响应提供 `availableMetrics`，后续刷新可自动恢复积分入口，不需再次发布客户端。其他鉴权、网络及服务错误仍按原错误处理。

## 数据与接口

- `matches.snapshot`：计分规则快照、结束事实、计分资格和结果更正版本。
- `match_players.snapshot`：本人得分及各项明细。内部角色 ID 仅供服务端更正计算，个人明细接口不返回同桌身份。
- `match_scores`：每局每位真实玩家一条（不含陪测账号），主键 `(match_id, uid)`；保存资格、分数、时间与明细。积分与战绩、房间保存、请求回执处于同一事务。重复提交不重复计分。
- `score_adjustments`：玩家独立调分流水，保存加减分、操作时的前后总分、原因与时间；`score_versions` 保存玩家积分版本，防止设置总分时覆盖新对局积分。
- `GET /api/scoring/rules`：公开的当前规则说明，不包含玩家信息。
- 房间公开视图 `scoreSettings`：本局开关值、是否可修改、默认开启人数阈值和计分资格提示；旧服务没有此字段时，客户端隐藏开关且不提交新参数。房主通过 `updateSettings` 的 `scoreEnabled` 布尔参数保存，复用阶段校验、事务及请求回执，修改开关记入操作审计。
- `GET /api/me/stats`：新增 `score`，包括总分、本月积分、计分局数、场均分、当前／最高连胜；阵营和角色分组附带积分统计。
- `GET /api/me/matches?offset=0&scored=1`：仅筛选计分局，包含 0 分局；不加筛选时显示完整历史。旧记录标记 `legacy`，排除局标记 `excluded`。
- `GET /api/me/score-adjustments?offset=0`：仅本人积分调整记录，每页 20 条，不返回账号或管理员身份；对局记录第一页也附带首批 `adjustments`，旧客户端可忽略。
- `GET /api/leaderboard?metric=points&period=month`：积分榜；至少一场计分局即可参加，同分并列。公开资格、分页版本、本人排名、公开开关与原榜单一致。本月按北京时间结束时间取半开区间。

房主结束本局时提交服务端提供的 `scoreReason`；刺杀型原因必须提供 `scoreTarget`（座位或 0 表示空刀）。服务端在结束操作中计算胜方与分数，不提供按座位查询身份或计分预览。结束界面只向本人展示其积分。

## 显示位置

“我的”显示总分、本月积分，并链接积分明细与规则；“我的战绩”展示场均、计分局数、连胜以及阵营／角色积分；“对局记录”展示每局分数、展开明细及排除原因；“排行榜”使用积分／局数／胜率三个主指标，胜率下再选择阵营。网页版同步提供上述内容和完整对局记录分页。

## 管理员更正

管理平台可按用户或房间分页查找归档对局，选择实际结束方式／目标即可更正，无需填写更正原因。更正使用本局原规则，同步更新胜负、积分、受影响的后续连胜奖励及仍可见的结束页面。请求编号保证重试幂等，结果版本防止并发覆盖，审计记录保存前后结果。

兼容旧后台的查询接口为 `GET /api/admin/matches?code=123456`（最近50场），更正接口为 `POST /api/admin/matches/:id/correct`，沿用管理平台鉴权及来源检查。旧局或不在计分范围的局不能补算积分。

## 后台积分管理

管理平台 `/admin` 的“战绩管理”包含“玩家积分 / 对局记录”两个标签页，均须管理员登录：

- **玩家积分管理**：按昵称、完整账号 UID 或公开 ID 查找玩家，可加减积分或设置总积分。操作保存为独立流水，不改变对局得分、胜负、连胜、计分局数或场均积分。流水计入总积分及操作当月积分，月份按北京时间。历史流水的前后总分表示当时操作结果。
- **对局积分与结果管理 → 本局玩家积分**：按房间号查找已归档对局，可一次修改多个玩家的本局得分，支持负分；也可逐人选择“恢复自动计分”。本局改分影响总分、场均和阵营／角色积分，仍归原对局结束月份；胜负与连胜保持原结果。更正整局胜负会重新计算后续连胜奖励，但已手动固定的本局得分继续保留，直到恢复自动计分。

玩家调分、单局调分和结果更正均无需填写原因，预览并确认后提交。写入、审计前后记录和请求回执在同一事务中完成；重复请求只生效一次，包括管理员重新登录后的重试。积分或对局版本已变化时拒绝覆盖，需重新查询。后台“操作记录”中，玩家调分位于平台操作，单局改分位于对应房间。玩家在自己的对局记录底部查看独立流水，历史备注继续保留。

关闭计分和旧历史排除局不能通过“本局玩家积分”转换为计分局；如需额外奖励，可使用独立玩家调整。仅有独立调整而没有有效计分局的玩家不获得积分榜资格。局数榜、胜率榜和趣味榜不受手动调分影响。

接口：

- `GET /api/admin/score-players?q=昵称&offset=0`：查找玩家，每页 50 条。
- `GET /api/admin/score-adjustments?uid=账号&offset=0`：玩家当前积分、版本及调整流水。
- `POST /api/admin/score-adjustments`：`uid`、`revision`、`mode`（`delta` 或 `set`）、`points`、`requestId`。`points` 为 -1000000 至 1000000 的整数。
- `GET /api/admin/matches/:id/scores`：单局积分、可编辑资格和对局版本。
- `POST /api/admin/matches/:id/scores`：`revision`、`scores`（`[{uid,points}]`）、`requestId`；`points: null` 恢复自动计分，整数范围同上。

旧客户端传入的 `reason` 仍兼容（可省略，至多 200 字），新后台不再收集该字段。

服务端启动时自动创建新增表。部署服务端即可启用后台管理，并让现有客户端总积分和榜单采用调整后的数据；发布本次小程序更新后，玩家可直接查看调整流水与原因。之后管理员日常调分以及既有规则配置调整均无需重新发布小程序。

## 对局记录管理

后台 `/admin → 战绩管理 → 对局记录` 支持按用户、房间或全部对局查询，每页 20 场。用户可按昵称、账号 UID 或公开 ID 查找；同名用户需核对账号标识。可按北京时间结束日期、记录状态和是否有陪测账号参与筛选，支持超过 50 场的历史分页。玩家积分页也可直接进入该用户的对局列表。

选择本页一场或多场记录后，可执行：

- **删除记录**：普通个人记录、近期记录和正式统计隐藏／排除本局。原始对局、得分和事实保留，管理员可在“已删除”筛选中恢复。
- **恢复记录**：恢复到删除前的状态；原来“不计战绩”的记录恢复后仍不计战绩。
- **不计战绩**：个人列表保留记录与原因，排除胜负、积分、趣味统计及排行榜。
- **计入战绩**：恢复原有统计资格；不补算原本未开启计分或缺少依据的积分。

这些操作影响整局所有参与者，即使从某个用户的列表进入也一样。每批最多 20 场，确认前展示所选对局、影响账号数及每人的有效局、胜场、总积分、当前连胜和趣味次数合计变化。趣味次数合计仅用于管理预览，各指标可能描述同一个事件。处理原因提供快捷选择，备注可选。混合状态会禁用不适用的操作。

原始结果与积分仍可在详情中查看。删除或不计战绩后暂不可编辑，须先恢复记录并计入战绩。已有结果更正和单局改分继续使用原规则；状态变更会重算受影响用户的后续连胜奖励，保留手动固定的单局得分和独立调分流水。网络结果未确认时冻结内容，使用同一请求编号重试；登录过期后重新登录可继续确认。

新增 `match_controls` 独立保存状态、删除前状态及原因。统计查询通过 `visible_match_players` 与 `active_match_scores` 视图统一筛选。状态、版本、积分重算、结束牌桌展示、审计及请求回执同事务提交；预览在保存点内模拟后回滚，不修改数据或缓存版本。重新保存旧房间、启动时重建投影与旧测试数据迁移不会撤销管理状态。记录没有永久删除入口。

管理接口：

- `GET /api/admin/match-records`：`uid`、`code`、`from`、`to`、`state`、`companion=1`、`offset`；状态为 `visible`（默认）、`active`、`excluded`、`deleted` 或 `all`。
- `POST /api/admin/match-records/preview`：`action` 与 `matches:[{id,revision}]`，返回影响预览。
- `POST /api/admin/match-records/manage`：同上，另含 `requestId` 与可选 `reason`；操作为 `delete`、`restore`、`exclude` 或 `include`。

### 开局时指定测试用途

小程序和网页版的房间设置增加“仅测试，不计战绩”。默认关闭，发牌后固定；修改会要求玩家重新准备，同房重开保留选择。启用后仍可测试完整结算流程并回查对局，但默认不进入正式胜负、积分和趣味统计。该设置与“允许陪测参与”和“本局计分”独立，陪测参与不影响同桌真实玩家的战绩资格；陪测账号自身不归档战绩、积分及趣味记录。管理员可从后台明确恢复计入，仍遵守原计分资格。

新增字段 `recordSettings`、`recordNotice` 与 `updateSettings.recordPurpose`（`normal`／`test`）。旧客户端仍正常使用；新版客户端遇到旧服务会隐藏用途开关且不发送该字段。用途归档到每场快照，后续修改房间不会影响历史局。先部署服务端，再更新小程序；后台清理能力随服务端部署启用。

陪测账号仅在有真实玩家的对局快照中保留昵称、座位、角色、最终阵营及存活状态，供展示同桌成员和管理员更正结算使用；不写入 `match_players`、`match_scores`、`match_fun_stats`，不因归档创建排行榜资料或积分版本。后台陪测筛选仍可查到混合对局，管理预览的影响账号数仅计算真实玩家。此调整适用于新归档，已有历史数据不自动删除。
