# 阿瓦隆十六人格测试实现规格

版本：2.0.0。面向 Codex 的可实现规格，包含全部题目、选项编码、角色原型、确定性计算、补题、结果内容和验收条件。用户语言为简体中文。

本版取代上一版泛化性格问卷：普通爪牙从结果中删除，加入会转换阵营的兰斯洛特；完整覆盖梅林躲刀/排水、忠臣装梅林挡刀、派的识别与保护、红队从知情差与保护链找梅林，以及换边后的策略调整。

交付范围是一个阿瓦隆主题的对局决策风格测试。28 道必答单选题，每题 3 个合法但有不同代价的策略；最多追加 2 道仅用于精确平局的题。8 个主角色各有 A/B 两个亚型，共 16 个结果。问题身份是场景条件，不直接给相同角色加分。

题目和画像是原创产品设定。结果描述本次策略偏好，不把选择视作实战正确率、找神能力、口才水平或心理测量结论。

## 1. 给 Codex 的实施指令

先阅读现有项目的 AGENTS.md、目录结构、技术栈及已有阿瓦隆页面，沿用当前项目约定实现一个“阿瓦隆十六人格测试”功能。以本规格与 quiz.json 为唯一内容和计分定义；scoring.mjs 是可直接复用或等价移植的纯函数参考。若只拿到本 Markdown，所有必需的题干、选项分值、角色向量和公式也已完整写在下文。

实现欢迎页、简要规则说明、逐题作答、进度与返回修改、自动保存、必要的平局补题、结果页和可分享的结果卡。先完成确定性数据与计算层，再接界面。无需后端或 LLM 判型；若接入已有后端，保留同样的纯函数结果。不得让模型自行改写题干、生成权重、补充隐藏规则或随机决定人格。

主角色排序完全不使用 E；E 只决定 A/B。任何“少说话”的选项不得被当成整体能力低。特别要让 Q13-A、Q14-A、Q15-B、Q16-B 这类选择能表现低公开介入、高身份追踪倾向。

按下文和 JSON 实现，不要求用户再决定题数、人格名单、维度、计分、同分策略或文案。现有项目不存在时可采用一个纯前端实现；具体框架沿用工作区条件，不改动无关功能。

## 3. 统一规则与已知信息

每题是独立的一局，座位与身份信息不跨题继承。history 只记录题干明确给出的任务，可能是部分记录；不能用数组长度推算当前轮次或比分，当前情境以 situation、phase 与 questNumber 为准。

| 配置 | 阵容 | 任务人数1–5 | 第4任务 |
|---|---|---|---|

| R9 九人局 | 蓝：梅林、派、4忠；红：莫甘娜、莫德雷德、刺客 | 3 / 4 / 4 / 5 / 5 | 至少2失败才失败 |

| O7 七人奥伯伦局 | 蓝：梅林、派、2忠；红：莫甘娜、刺客、奥伯伦 | 2 / 3 / 3 / 4 / 4 | 至少2失败才失败 |

| L9 九人兰斯局 | 蓝：梅林、派、3忠、初始蓝兰；红：莫甘娜、刺客、初始红兰 | 3 / 4 / 4 / 5 / 5 | 至少2失败才失败 |

**R9 的额外信息约定必须显示给玩家：**为覆盖“已知队友莫德雷德”等情境，本题库九人红方题采用“红方互认时确认彼此具体角色”的配置。这是本题库明确给定的附加信息，不是基础规则默认自动提供的信息。O7、L9 不继承此约定。梅林仍不会自动区分红方具体角色，在 R9 也看不到莫德雷德。

其余基础限制：好人必须投成功，红方可投成功或失败；一张失败只证明至少有人出失败，不能证明车上恰好一个坏人；成功任务也可能藏红。单边派只是唯一宣称派的人，不能机械确认真派。派看到的是梅林/莫甘娜两名候选，不是已经区分好的两个身份。O7梅林看到全部3名红方，但不知道各自红角色，也不知道其他好人是派还是忠。

“排水”在本测试中指梅林呈现普通好人能够拥有的依据与不确定性、控制信息指纹以降低被刺嫌疑，不要求故意送任务。“挡刀”指好人通过身份表演、真实行为或保留多候选分担梅林嫌疑。纯粹给其他人保留梅林嫌疑以保护自己，不直接计成替人承刀。

L9 统一采用 Big Box 兰斯变体1：两兰不互认；初始红兰不睁眼，但其他红方认识他；每个任务开始、组队前从4张不变和2张转换组成的牌堆抽牌，不放回，抽牌结果公开。转换时两兰同时变更阵营，身份牌不交换，后续不重开夜间互认。当前蓝兰必须成功，当前红兰可成功或失败；不混用变体2的红兰强制失败规则。

所有选择只能用正常公开发言、组队、投票与合法任务牌。不给翻牌证明、场外信号或私聊串通选项。刺杀阶段题统一约定落刀前可有一次简短公开发言，此时不再出任务。

基础人数、任务、身份与刺杀规则参考[基础规则书](https://www.spelhuis.be/Files/7/112000/112353/Attachments/Product/U9938c0U53sX1M6G30365Eg47R7GR0Ou.pdf)；兰斯变体参考[Big Box规则书转录中的Variant 1](https://www.rulespal.com/avalon-big-box/rulebook)。R9具体身份互认、题目情境、选项编码、人格画像与算法阈值均为本方案明确设定。

## 4. 16种人格及其呈现

A＝主动介入：更愿意发起、公开承担讨论压力。B＝低曝光择机：更愿意少量表达、控制介入时点。A/B均不是能力高低、善恶、稳定/焦虑或MBTI的A/T。内部代码用于结果存储，对外标题使用角色名和称号。

| 主角色 | A型 | B型 | 核心偏好 |
|---|---|---|---|

| 梅林 | MER-A 执炬先知 | MER-B 雾幕先知 | 控制信息泄漏，在任务推进与躲刀之间安排引导方式。 |

| 派西维尔 | PER-A 执盾辨影者 | PER-B 静默守望者 | 围绕真假信息源建立信任，同时避免把保护对象暴露得过清楚。 |

| 亚瑟的忠臣 | LOY-A 替身骑士 | LOY-B 磐石卫士 | 依靠公开证据推进任务，也愿意通过可解释的行为帮助关键好人分担压力。 |

| 莫甘娜 | MOR-A 镜像导演 | MOR-B 暗语织影者 | 关注别人怎样理解线索，通过叙事、信任和呈现方式影响身份判断。 |

| 莫德雷德 | MOD-A 暗局统筹者 | MOD-B 深潜执棋者 | 把隐藏位置、公信力与队友配合视为可持续使用的阵营资源。 |

| 刺客 | ASS-A 追问猎手 | ASS-B 静默猎手 | 追踪谁在什么时候知道了什么，用身份证据收敛最终指认目标。 |

| 奥伯伦 | OBE-A 破局游侠 | OBE-B 孤影观察者 | 在缺少稳定同盟信息时保留独立路线，不轻易把临时同向当成确认队友。 |

| 兰斯洛特 | LAN-A 转势骑士 | LAN-B 藏锋骑士 | 新阵营或新证据改变目标时，重新安排旧承诺、信誉与行动。 |

### 梅林的结果内容

- A型：更愿意主动铺出可被普通好人接受的线索，必要时承担引导压力。
- B型：更愿意保持普通好人的信息边界，通过少量提示与排水控制刀口。
- 可能有帮助的倾向：习惯同时考虑信息传递和暴露成本。
- 常见代价：提示过少可能让队友无法跟上，排水过多也可能损害任务线。
- 一条建议：把公开依据与夜间所知分开，给队友足够行动信息。

### 派西维尔的结果内容

- A型：更愿意主动比较候选、追问立场，并替可信方向承担压力。
- B型：更愿意延后身份承诺，通过长期观察与分散绑定保护候选。
- 可能有帮助的倾向：愿意维护关键同盟，并反复检查信任依据。
- 常见代价：保护过于集中可能暴露身份链，也可能替错误对象背书。
- 一条建议：把暂时信任与确认身份分开，避免连续替同一个人解释一切。

### 亚瑟的忠臣的结果内容

- A型：更愿意公开担责，必要时用真实记录或适度装梅林吸引刀口。
- B型：更愿意保持稳定记录，少做无依据的身份承诺，以可靠配合留下身份模糊空间。
- 可能有帮助的倾向：重视把团队需要的判断讲清楚，并寻找可执行的配合。
- 常见代价：承担太多无把握的身份表演可能损失公信力；过度求稳也可能缺少掩护。
- 一条建议：先确定自己的行动能被公开记录支撑，再决定承担多少身份注意。

### 莫甘娜的结果内容

- A型：更愿意主动搭建一套解释，争取被对方当成可信的信息源。
- B型：更愿意借已有信任与他人的代言，少量修饰、择机引导。
- 可能有帮助的倾向：对叙事视角与信任关系敏感。
- 常见代价：过多替代解释容易前后不一致，借别人代言也会失去部分控制。
- 一条建议：每次改变解释前先核对自己已留下的公开记录。

### 莫德雷德的结果内容

- A型：更愿意利用隐蔽身份主动安排队伍结构和行动分工。
- B型：更愿意保留盲点与后手，减少无收益的绑定和暴露。
- 可能有帮助的倾向：愿意规划结构与资源，保留后续行动空间。
- 常见代价：过度保护自己可能让队友承压，等待过久也可能错过任务窗口。
- 一条建议：给自己的隐蔽资源设置明确使用时机，而非无限留到以后。

### 刺客的结果内容

- A型：更愿意通过有针对性的公开问题检验候选，再承担最终判断。
- B型：更愿意回看信息时间线和保护链，少说话也持续整理刀口。
- 可能有帮助的倾向：关注信息来源，倾向把发言气势与知情程度分开看。
- 常见代价：容易过度解释一次准确或一次失误，也可能为找神放弃可争取的任务收益。
- 一条建议：每个刀口都保留一个普通好人解释，并检查最早的信息来源。

### 奥伯伦的结果内容

- A型：更愿意自己制造变化或承担一次行动，获取新的判断入口。
- B型：更愿意独立观察关系和反应，等信息足够后再介入。
- 可能有帮助的倾向：愿意保留与主流不同的解释，并自行推进一条线。
- 常见代价：独立判断可能与队伍动作冲突，缺少沟通也可能错失配合。
- 一条建议：区分临时合作与确认身份，在关键动作前给出可理解的公开理由。

### 兰斯洛特的结果内容

- A型：更愿意明确重设方向，主动处理变化带来的信用成本。
- B型：更愿意保留可用关系与外在连续性，逐步把行动转到新目标。
- 可能有帮助的倾向：愿意重新检查旧计划，并在变化中保留有用资源。
- 常见代价：转向太快会让人无法跟上，转向太慢可能让旧承诺拖住当前目标。
- 一条建议：明确哪些目标已改变、哪些事实仍成立，再决定需要公开多少变化。

## 5. 八个独立编码维度

前七维决定角色；最后的 E 仅决定亚型。负值不代表弱，正值不代表强，都是策略取向。每题只测它声明的2–3个维度，未测的维度不进入该题的分子或分母。

| ID | 维度 | 负端 | 正端 | 用途 |
|---|---|---|---|---|

| D | 推理入口 | 任务、票型与行动因果 | 知情边界、信息来源与保护链 | 主角色 |

| H | 信息暴露 | 让依据明确、可追溯 | 控制信息指纹与身份暴露 | 主角色 |

| S | 身份掩护 | 保留自身公信力与行动位置 | 承担身份嫌疑，为别人掩护 | 主角色 |

| W | 收益重心 | 优先任务线收益 | 优先终局身份收益 | 主角色 |

| F | 表达策略 | 沿可核验依据表达 | 设计叙事、替代解释与观察框架 | 主角色 |

| U | 协作路线 | 稳定联动、整合队友判断 | 独立分线、自主承担判断 | 主角色 |

| R | 计划调整 | 保留连续计划与既有承诺 | 按新证据或当前阵营重构计划 | 主角色 |

| E | 介入风格 | 低曝光、择机介入 | 主动发起、公开承担压力 | 只决定A/B |

原始分值为 −2…+2 的作者编码，不是玩家得分。raw=0 表示不额外强调任一端；统一题内中心化后，0表示相对本题可选策略的中点，不能与未测或未答混同。权重与原型属于创作先验，先固定实现，后续只在版本升级中依据实际试答修订。

## 6. 完整28题及逐选项计分

答题页仅显示配置提示、自己的身份、具体情境、问题与三条选项。下列计分表、作者说明、解释与代价供实现和结果解释使用，不在选项旁提前展示。无标准正确答案，也无答完单题立即显示人格增减的反馈。

### Q01 单边派带出的首轮失败

主题：组队与站边。配置：R9（九人局·红方具体身份互认）。

你是1号忠臣。第一任务队伍为2、3、4，出现1张失败票。2号是唯一宣称派西维尔的人，但未被规则验明身份。3、4互相怀疑；3的发言更完整，其他场外玩家暂无明显信息差。第二任务需要4人。

**你更愿意优先推动哪一种组队思路？**

- **A：**暂时保留2，把3、4都换掉；建议1、2、5、6，用新成员重新建立任务记录。

- **B：**暂时保留2，再留更能说明自己判断何时形成的3；建议1、2、3、5，继续检验3而不是同时淘汰两人。

- **C：**先核2凭什么默认获得信任，取消单边派保送；把三人重新放回待判断名单，提出1、5、6、7这条独立路线。

开发计分：

| 选项 | D | R | U |
|---|---|---|---|

| A | -2 | +0 | -1 |

| B | +1 | -1 | -1 |

| C | +1 | +1 | +2 |

- A解释：倾向同时替换失败队中的两名争议成员，再沿暂时信任的节点推进。 代价：单边派未验明；新换入的5、6也没有因此成为好人。

- B解释：愿意参考发言背后的信息来源，保留一个相对可信者继续检验。 代价：解释完整不保证身份；你保留了原失败队的两人。

- C解释：不让单一身份宣称锁住自己的分析路线。 代价：完全换车损失已有连续信息，新队也可能有坏人。

作者校验：一张失败票只保证至少一个人出失败。单边派不等于确认好人。这里比较策略顺序，不声称三条路线安全概率相同。

### Q02 双派中的热门一方刚刚发车失败

主题：组队与站边。配置：R9（九人局·红方具体身份互认）。

你是1号忠臣。2号X和3号Y都跳派。第一任务前多数人站X；X提出的2、4、5被通过，结果1张失败。X、Y事后解释力度接近，你没有新的身份信息。第二任务需要4人。

**你下一次发言更接近哪一种？**

- **A：**明确把暂时信任转向Y，请Y先给第二任务名单与理由；仍不把Y当成已确认真派。

- **B：**继续暂时站X，要求他解释如何调整名单；一次失败还不足以推翻此前判断。

- **C：**先不抢发言、不交派边；轮到自己时简短提出1、4、6、7这支不含双派的四人队，再听别人比较名单。

开发计分：

| 选项 | R | U | E |
|---|---|---|---|

| A | +2 | -1 | +1 |

| B | -2 | -1 | +1 |

| C | +0 | +2 | -2 |

- A解释：愿意让失败结果触发较大幅度的站边更新。 代价：失败可能来自4或5；转向Y可能只是换到另一条错误路线。

- B解释：倾向先修正现有计划，而不是立即更换信任中心。 代价：先前站边可能形成锚定，让你低估新问题。

- C解释：以择机、低曝光的方式保留独立任务路线。 代价：避开双派不等于安全，4也在首轮失败队。

### Q03 莫甘娜面对队友假派和场外派

主题：组队与站边。配置：R9（九人局·红方具体身份互认）。

| 选项 | R | H | S |
|---|---|---|---|

| A | +2 | -2 | +2 |

| B | +0 | +2 | +0 |

| C | -2 | +0 | -2 |

- A解释：愿意公开重构叙事并承担身份与信用成本。 代价：别人可能不信身份宣称，你也无法确认2、3没有隐藏红方。

- B解释：通过控制暴露的方式修正过去的误导。 代价：修正可能不够彻底，其他好人未必理解你的变化。

- C解释：愿意保留过渡过程，用连续行动重新建立合作。 代价：放弃当前位置也可能削弱好人可用的信息和配合。

作者校验：只能确认自己贡献了那一张失败；同车其他红方可能投成功。当前蓝兰上车必须成功。

### Q28 旁观者怎样面对兰斯身份变化

主题：兰斯洛特与阵营变化。配置：L9（九人兰斯洛特局，Big Box变体1）。

你是1号忠臣。4、7此前分别宣称自己是初始蓝兰、初始红兰，没有翻牌认证。前两次阵营牌均不变，任务一成一败；第三任务开始公开抽到转换。4、7都声称自己已换边。你此前更信4属于好人，但一直不确定他是真蓝兰，还是普通好人在假跳兰斯。第3任务需4人。

**你接下来怎样安排判断与组队？**

- **A：**按“他们是真兰或是假跳”分别重建分支，公开要求两人解释换边前后准备怎样行动。

- **B：**暂时保留对4的信任倾向，先看其具体名单；一张转换牌不能证明4的身份，也不足以自动推翻旧判断。

- **C：**本轮先提出1、2、3、5，不以4、7的身份为组队前提，观察二人对新路线的反应。

开发计分：

| 选项 | R | U | E |
|---|---|---|---|

| A | +2 | +0 | +1 |

| B | -2 | -2 | -2 |

| C | +0 | +2 | +1 |

- A解释：愿意把公开变化纳入模型，同时保留身份宣称的真假分支。 代价：分支较多，解释和讨论成本上升。

- B解释：倾向延续既有合作，再逐步吸收变化。 代价：可能低估真实换边带来的目标改变。

- C解释：愿意独立开一条不依赖争议身份的行动路线。 代价：新队同样未经确认，也可能错失真实蓝兰的合作。

## 7. 确定性计分算法

### 7.1 先校验完整答案

输入为按稳定ID索引的对象：`{Q01:"A", Q02:"C", ...}`。主问卷必须28题都有合法选择。未知题目ID、未知选项ID和数组形式答案应报错；缺题返回 `incomplete` 和缺题列表，不能补零。UI以map保存每题唯一当前选择，修改答案覆盖该题值；若后端接收记录数组，应在转换map前拒绝重复题ID。

### 7.2 题内中心化与维度归一

对每题 q 的每个已测维度 d：

```text
mu[q,d] = mean(raw[q,A,d], raw[q,B,d], raw[q,C,d])
c[q,o,d] = raw[q,o,d] - mu[q,d]
m[q,d] = max_o(abs(c[q,o,d]))
M[d] = sum_q m[q,d]          // 仅累加测了d的主问题
x[d] = sum_q c[q,selected,d] / M[d]
```

每维 x 在[-1,1]内；每题未声明的维度不计入。若三个选项某列完全一样，则m=0，该维没有区分信息，配置校验必须报错。中心化只消除三个选项整体偏向造成的设计基线，不代表心理学校准。不得用回答数量取代M，也不得把缺省字段当成额外中性回答。

### 7.3 角色原型与得分

以下顺序固定为 `[D,H,S,W,F,U,R]`，不含E。

| 角色ID | 原型向量 |
|---|---|

| merlin | `[-1, 2, 1, 2, -1, -1, 0]` |

| percival | `[2, 0, 2, 1, -1, -2, -1]` |

| loyal | `[-2, -2, 1, -2, -2, -1, 0]` |

| morgana | `[1, 1, 0, 1, 2, -1, 1]` |

| mordred | `[-1, 2, -2, -1, 1, -1, -1]` |

| assassin | `[2, 1, -1, 2, -2, 1, 0]` |

| oberon | `[1, 0, 0, 0, 0, 2, 0]` |

| lancelot | `[0, 1, 0, -1, 0, 0, 2]` |

```text
pUnit[role] = prototype[role] / sqrt(sum(prototype[role]^2))
score[role] = sum_d x[d] * pUnit[role,d]      // d只遍历前7维
```

取未舍入最高分。原型归一避免某个角色因向量长度更大天然占优。角色分允许为负，它是原型偏好分，不是匹配概率或正确率。不得先取整、转百分比或用LLM覆盖结果。

### 7.4 A/B亚型

`x[E] > 1e-10` 得A；`x[E] < -1e-10` 得B；其余视为计算同分，追加T_STYLE。E不进入任何主角色计算，主角色也不能反向决定E。

### 7.5 接近与精确平局

常量 `epsilon=1e-10`。最高分减候选分不大于epsilon的角色构成精确并列集合。只有一个最高者直接采用；多个最高者追加T_ROLE，只在这组候选中决定第一。不能按数组顺序、角色名称、随机数或用户ID散列选一个。

角色只是接近、没有精确并列时，不触发T_ROLE，也不改变最高者。为了提示结果边界，计算：

```text
norm = sqrt(sum_d x[d]^2)                  // 前7维
signalStrength = norm / sqrt(7)
cosineGap = max(0, (score[primary] - score[runnerUp]) / norm)
// norm<=epsilon时cosineGap=0
```

如果使用过T_ROLE，或者 signalStrength<0.15，或者 cosineGap<0.10，显示“混合倾向”并展示最多两个次接近角色；否则显示“相对鲜明”。这两个阈值是界面解释规则，没有统计置信度含义。计算时保留浮点精度，仅最终图形显示可舍入。

### 7.6 T_ROLE 仅在主角色精确并列时出现

你是9号刺客，认识2号莫甘娜和8号莫德雷德。当前2蓝1红，下一轮第4任务5人且需2失败。两个好人都可能掌握额外信息，时间只够先推进一件事。

**你优先做哪件事？**

- **A：**回看两人在信息尚未公开时的判断，按知情边界排序最终指认目标。　补题向量：`{"D": 2, "W": 1, "F": -1}`

- **B：**围绕现有任务记录设计一套对己方有利的替代解释，争取有利组队和足够的己方配合。　补题向量：`{"D": -1, "W": -2, "F": 2}`

- **C：**对照两人的上车、否决和任务轨迹，用已有行动记录缩小最终指认范围。　补题向量：`{"D": -1, "W": 1, "F": -1}`

只对原并列集合中的角色计算 `tieScore=sum_d tieAnswer[d]*pUnit[role,d]`，d为D/W/F；不除主问卷分母，不把补题加入28题画像，也不让非并列角色逆袭。选择最高投影者，记录 `roleResolution="role_tiebreak"`。当前原型已验证三个选项各自对八个角色的投影均两两不同，任意并列子集都能唯一决胜；修改原型后必须重新验证这一性质。

### 7.7 T_STYLE 仅在E精确同分时出现

你是忠臣。当前2蓝1红，第4任务需5人且需2失败。桌上已有你认为可接受的名单，但几个人仍在犹豫，你没有额外身份信息。

**你更自然地怎样参与最后这段讨论？**

- **A：**主动把自己支持的依据讲清楚，推动大家完成比较，并承担这次表态。 → A型

- **B：**先听完分歧，只在出现关键遗漏时简短补充，保留低曝光的参与方式。 → B型

此补题仅决定亚型，记录 `subtypeResolution="style_tiebreak"`，保留原画像E=0，结果解释为“介入方式较均衡，本次按补充选择归入此亚型”。若同时需要两个补题，依次展示T_ROLE、T_STYLE。最多30题。返回修改任何主答案时清空旧补题答案并重算，只展示仍然需要的补题。

## 8. 结果页与解释生成

结果必须包含：角色与亚型标题、角色核心描述、该亚型的介入方式、一条可能有帮助的倾向、一个代价、一条建议、七维偏好与独立的E倾向、2–3条能回溯到真实答案的解释、必要时的次接近角色。视觉上的16张卡片对应16个typeId，不增加隐藏类型或稀有度。

scoring.mjs按“所选选项对主角色相对第二名的贡献”选出最多3条解释。每条必须引用真实questionId/optionId对应文本与interpretation，不编造用户没选过的行为。若整体较均衡，优先显示混合倾向，不用强断言把一个弱结果写得很确定。

不展示“匹配度100%”“找梅林能力90分”“比多少人聪明”“某阵营人格更坏”等字段。可以把维度映射成倾向条，但必须叫“本次相对偏好”，不叫能力雷达或人群百分位。A/B只是表现风格，两个亚型没有等级。

`scoreQuiz`返回状态为 `incomplete` / `needs_tiebreak` / `complete`。未complete时不能显示已定人格。complete返回version、roleId、subtype、typeId、title、profile、rankedRoles、secondaryRoleIds、tendencyLabel、两类resolution及explanations；精确原始分仅供开发诊断，不必直接呈现给玩家。

## 9. 前端交互与数据保存

- 一题一屏，显示自己身份、配置徽标、清楚的具体情境、3个大选项和进度；长题允许滚动，但选项不截断。
- 规则术语提供随时展开说明：单边派、排水、挡刀、红方已知信息、第四任务、兰斯变体。
- A/B/C是内容内部ID，前端可稳定打乱展示顺序，但始终存原optionId；不能按第几个按钮计分。
- 保留上一题、修改、自动保存和继续答题。保存键至少包含问卷version；恢复旧版本不能静默套新权重。
- 作答期间隐藏分值、原型、人格预告和作者评语，减少按想要的结果反选。
- 结果卡可用基础角色形象加亚型称号，按现有项目资源实现；不要把制作新插画作为计分功能的阻塞项。
- 所有状态需能用键盘操作，选项具有明确选中状态；窄屏不出现横向溢出。

## 10. 验收与已完成的配置检查

运行 `node validate.mjs`，无需安装第三方依赖。它会读取题库与可达性见证，并生成validation-report.json。

当前版本已通过16/16类回答见证的独立JavaScript复算；最小第一名领先分为0.940944。这只证明计分路径确实可达，不证明心理学有效性。

| 维度 | 有效测量题数 |
|---|---:|

| D | 7 |

| H | 14 |

| S | 6 |

| W | 9 |

| F | 9 |

| U | 11 |

| R | 9 |

| E | 18 |

已检查配置合法、16型全部可达、题目与选项展示顺序不影响结果、E变化不改变主角色、缺失/非法答案不会补0、主角色同分只在原并列集合决胜、E同分独立补题、任务记录人数与失败票合法，以及Q06的一红第四任务必能成功这一条件。

analysis_report.json另保留50,000组均匀随机主答案的配置分布，作用是发现某个类型几乎不能出现等设计异常。它不是人群占比、人格准确率或产品转化数据，不应作为结果页“稀有度”。上线后用真实试玩检查题意、策略区分和反馈，再版本化调整。

改动分值、原型或补题时，应更新version，重新生成16型见证并运行验证。纯展示修改只需验证题干/选项完整、稳定ID和状态恢复不变；不需重新做无关的大规模测试。

## 11. 最小使用示例

```js
import {scoreQuiz, validateConfig} from "./scoring.mjs";
// quiz从quiz.json导入；answers由表单以稳定ID维护。
validateConfig(quiz);
const result = scoreQuiz(quiz, answers, tieAnswers);
if (result.status === "incomplete") { /* 展示缺题 */ }
else if (result.status === "needs_tiebreak") { /* 依次展示pendingQuestionIds */ }
else { /* 按result.typeId显示结果，并带上version */ }
```

不得用“选了哪一个角色的情境题”“A选项较多”“回答字数较长”替代上述模型。所有业务解释均从实际选择和配置中的文字生成；角色题中的已知信息不等于用户现实具备该能力。
