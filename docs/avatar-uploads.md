# 自定义头像

小程序支持选择自己的图片作为头像，保留五种风格共160款内置头像。图片审核通过后点击「保存资料」生效；上传、等待审核、失败、取消或离开编辑页不改变当前资料。网页版仍只提供内置头像选择，并展示账号在小程序保存的自定义头像。

## 启用与发布

生产默认关闭。先部署服务端，在微信小程序管理后台配置消息推送，再发布小程序。服务端配置如下（真实凭据只放在服务器环境中）：

```dotenv
AVATAR_UPLOADS=1
AVATAR_PUBLIC_ORIGIN=https://<API域名>
WECHAT_APP_ID=<现有小程序AppID>
WECHAT_APP_SECRET=<现有小程序AppSecret>
WECHAT_MESSAGE_TOKEN=<微信消息推送Token>
WECHAT_MESSAGE_AES_KEY=<微信消息推送43位EncodingAESKey>
```

消息接收URL为 `https://<API域名>/api/wechat/avatar-review`，消息格式选 **JSON**、加密方式选 **安全模式**，Token及EncodingAESKey与环境配置一致。接口支持URL验证与加密审核事件，验证签名、解密后的AppID、事件类型及版本；不接受明文审核事件。后台配置前先部署带上述配置的服务，使验证URL可访问。若已经有消息接收服务，需要让现有接收服务转发完整加密请求至此接口，或先整合回调路由，避免覆盖其他已用消息功能。

微信后台将API的HTTPS域名同时加入 **request合法域名** 和 **uploadFile合法域名**。`AVATAR_PUBLIC_ORIGIN` 必须是不含路径或末尾斜线的HTTPS源地址，微信审核服务器需能下载其临时图片路径。检查网关的请求体上限不低于 `2MB + 8KB`。按实际功能更新隐私说明：头像用于个人资料、牌桌、排行榜和生成分享图片；图片会传给微信内容安全服务审核。

缺少审核必需配置时上传能力关闭，原有功能继续工作。设 `AVATAR_UPLOADS=0` 可关闭新上传，已保存的头像仍继续展示。不要关闭安全审核来处理上游故障。尚未保存的上传草稿不属于正式资料，超过24小时需要重新选择图片。

本地执行 `AVATAR_UPLOADS=1 npm run dev`，同时将小程序连接到本地开发服务。开发登录使用模拟审核，不请求微信；生产环境禁止开发登录，不使用模拟审核。测试替身只用于自动化测试。微信选择器、合法域名和真实审核回调需要真机验收。

## 上传与保存

1. 小程序调用 `chooseAvatar`，本地预览选择的图片，再调用 `wx.uploadFile`。微信账号每次上传另取一个 `wx.login` code，服务端核对该code对应的账号与当前会话相同。原始OpenID只用于当次审核，不写入数据库，账号uid和原有登录接口保持不变。
2. `POST /api/me/avatar-uploads` 要求Bearer会话及幂等键，multipart含一张 `file` 和微信账号的 `code`。仅小程序微信账号可上传；本地开发账号可联调。游客和陪测账号不开放上传。
3. 服务端限制2MB、1600万像素，真正解码JPG/PNG、按方向旋转、居中裁剪至256×256、去除元数据并编码为不超过256KB的JPG。每账号最多5次上传请求/分钟，图片处理与审核提交最多并发4个。
4. 图片仅存在 `avatar_uploads` 草稿表，状态为 `processing/pending/approved/rejected/failed`，24小时到期。响应仅返回本人上传编号、状态、到期时间。`GET /api/me/avatar-uploads` 返回是否开放上传；`GET /api/me/avatar-uploads/:id` 仅本人查询。
5. 服务端调用微信 [media_check_async v2](https://developers.weixin.qq.com/miniprogram/dev/server/API/sec-center/sec-check/api_mediacheckasync.html)，使用资料场景 `scene=1`、图片类型 `media_type=2`。临时图片地址带256位随机令牌、禁止缓存、到期失效，不使用正式公共头像路径。微信回调 `pass` 才通过，`risky/review` 拒绝，上游错误标记失败。
6. 用户点击保存，普通资料接口提交 `avatar: "upload:<id>"`。同一事务核对本人归属、通过状态、有效期、资料版本及幂等编号，将图片去重存入原有 `avatars` 表，绑定 `profiles.avatar_hash`。提交后统一使用 `/api/avatars/:hash`，资料、牌桌、排行榜、网页版和分享图片沿用原展示路径。

普通资料请求仍限8KB，继续接受 `builtin:<id>`、`null`（清除）和省略头像字段（保留）；不接受图片Base64或外部地址。网络结果未确认时重试相同图片及上传编号，服务端复用上传记录，不重复审核；明确审核失败后可以新编号重传。保存结果未确认时仍重试原资料请求。旧客户端与未启用上传的服务器继续使用内置头像。

审核等待只轮询草稿状态，不自动保存。更换为内置头像、重新选择图片或离开页面后，迟到结果不覆盖当前编辑内容。微信文档说明审核结果可能在30分钟内推送，页面自动检查一段时间后提供「继续检查审核结果」；也可直接选择内置头像保存。

## 存储、清理与验证

图片仍存SQLite，沿用已有备份。过期上传草稿随既有维护任务分批清理；审核拒绝或失败立即移除草稿图片数据。仅本次功能新增的自定义头像进入清理追踪，当前资料引用、有效上传草稿与仍存续的保存回执均受保护。失去引用的图片至少保留 `RECEIPT_RETENTION_DAYS`（默认90天），保护保存重试和缓存；内置及旧版头像不批量删除。清理仍以近期成功备份为前提。

自动化测试覆盖图片解码、大小/像素限制、元数据移除、归属与身份校验、审核回调签名/加密、幂等、版本冲突、失败/过期、跨重启、清理保护、牌桌/榜单展示，以及前端等待、取消、重试与迟到结果。上线前在真机完成选择、上传、审核回调、保存、牌桌、排行榜及分享图验收。
