# 小程序扫码确认网页登录

网页版默认游客，在“我的”可选择“使用小程序账号登录”。扫描网页的小程序码后，在小程序核对账号、网站与设备并点击确认，网页即使用同一个 `wx:` 用户。资料、积分、战绩、榜单开关和座位都读取原用户的数据，不复制小程序会话，不依赖 UnionID，不自动迁移或合并游客数据。

## 发布顺序

1. 部署包含此功能的服务端，保持 `WECHAT_WEB_LOGIN=0`。现有小程序 `/api/login`、游客入口、对局接口继续可用。
2. 上传、审核并发布新增页面 `pages/web-login/web-login` 的小程序版本。保留当前 AppID、HTTPS baseUrl 与合法 request 域名，不启用 devAuth。旧小程序页面和登录流程不需要改动。
3. 确认服务端已有匹配此小程序的 `WECHAT_APP_ID`、`WECHAT_APP_SECRET` 与 `WEB_ORIGIN`，然后设 `WECHAT_WEB_LOGIN=1` 并重启服务。两项微信凭据缺失时入口仍关闭。无需网站应用 AppID、公众号或新增云开发服务。
4. 使用正式微信账号扫描网页新生成的小程序码，核对小程序显示的域名与账号，确认后检查网页资料、战绩和已有座位；退出网页后检查小程序仍登录。至少在两台设备、两个独立浏览器验证二维码不能互相领取。

码服务调用微信 `stable_token` 与 `getwxacodeunlimit`，固定 `env_version=release`、`check_path=true`。需要微信后台为该小程序开放相应接口，服务端可访问微信 API；如果后台要求出口 IP 白名单，配置实际服务出口。未发布确认页通常返回 41030，网页显示“确认页尚未发布”，不会降级为跳过确认。凭据与接口权限应在实际微信后台核验；本地测试不能替代正式账号真机验收。

回退时先设 `WECHAT_WEB_LOGIN=0`，停止新扫码请求；已签发网页会话仍可使用并退出，小程序与游客登录不受开关影响。数据库只新增表；不要修改已有 `wx:` 或 `guest:` 用户 ID。

## 行为约定

- 浏览器保留有效登录时直接恢复。网页微信会话最长 30 天；过期后提示重新扫码，并提供明确的游客选项，不自动切成新游客。
- 登录后原游客凭证保留在本浏览器；“退出并返回原游客”只撤销当前网页会话。游客凭证仍有效时恢复原资料，已过期或被清理时只能创建新游客，不能凭昵称找回。
- 不迁移游客战绩、积分、昵称或座位。当前用户在准备牌桌入座或担任房主时须先离开；进行中须等本局结束。服务器在创建请求、确认和领取时检查原游客状态，退出时检查当前微信用户状态。
- 同一个微信用户的网页与小程序共用座位。现有对局阶段检查、幂等键和资料版本检查继续约束操作。
- 小程序扫码只展示请求，不自动确认；拒绝、浏览器取消、刷新码及两分钟超时均终止旧请求。暂不提供配对码、公众号授权、开放平台网站登录或手机直接唤起。

## 接口与凭据边界

| 接口 | 授权与用途 |
| --- | --- |
| GET `/api/web-auth/session` | 同源浏览器读取开关和当前 Cookie 会话摘要，无令牌、UID |
| POST `/api/web-auth/requests` | 同源创建；可携带现有游客 Bearer，记录待切换身份 |
| GET `/api/web-auth/requests/:id` | 原浏览器绑定 Cookie 查询状态 |
| POST `/api/web-auth/requests/:id/claim` | 原浏览器领取已确认的会话；响应丢失可幂等重试 |
| POST `/api/web-auth/requests/:id/cancel` | 原浏览器取消未领取请求 |
| POST `/api/web-auth/requests/:id/inspect` | 小程序 `wx:` Bearer 查看并锁定扫码账号 |
| POST `/api/web-auth/requests/:id/confirm` | 同一小程序账号明确确认 |
| POST `/api/web-auth/requests/:id/reject` | 同一小程序账号拒绝 |
| POST `/api/web-auth/logout` | 同源撤销当前网页会话和该浏览器的授权请求 |

小程序仍使用原 `sessions` 表和 Bearer token。网页微信身份使用独立 `web_sessions` 表以及 HttpOnly / Secure / SameSite=Strict / `__Host-` Cookie。网页请求附会话摘要 `X-Web-Session`，防止旧标签页在账号变化后将操作提交到新账号。Cookie 会话必须符合 Host、非跨站检查，写入另校验 Origin。无 Cookie 时带旧会话摘要也不会回退到游客认证。

同域管理陪测使用有效 `test:` Bearer 令牌识别测试玩家，不使用浏览器的玩家登录 Cookie；请求仍须通过管理员 Cookie、Host／Origin、管理员会话归属与测试房间范围校验。网页登录切换或过期不会改变陪测身份。本地 `/dev` 面板仅发送独立 Bearer 令牌，不携带浏览器 Cookie。普通玩家和游客请求继续执行上述网页会话校验。

`web_login_requests` 存储短期授权状态。小程序码只携带随机 128 位请求 ID（32 个十六进制字符），领取另需随机浏览器绑定 Cookie。请求和会话哈希持久化至 SQLite，重启后保持；请求已消费后只允许原浏览器重取同一未撤销的会话，不再创建新会话。创建码、扫码确认和轮询均限流，过期请求与会话会清理。原游客 token 从不升级为微信权限。

## 验证

`npm test` 包含服务端全流程、安全边界、响应丢失重试、过期、座位冲突、重启、微信接口故障、前端状态隔离、小程序页面逻辑和 WXML/WXSS 编译回归。微信上游在自动化测试中使用注入的固定适配器；不使用真实密钥，不发起真实微信授权。
