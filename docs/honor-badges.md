# 荣誉徽章与永久活动纪念

## 2026年10月内测纪念

新增五枚永久徽章，与原有18枚月榜徽章一起展示在「荣誉收藏」中：

| 徽章 | 资格 |
| --- | --- |
| 加冕圣剑 | 发布时锁定的10月公开积分榜第1名 |
| 银盔骑士 | 发布时锁定的10月公开积分榜第2名 |
| 林间守望 | 发布时锁定的10月公开积分榜第3名 |
| 共建圆桌 | 北京时间10月至少参加1场正常归档游戏，不要求计分或胜负记录 |
| 内测纪念册 | 北京时间10月至少参加1场计分对局，零分计分对局也符合 |

服务入口 `server/index.js` 启动时，在一个事务中创建 `2026-10-beta` 活动快照并立即授予前三名及已有参与者。积分排名复用现有公开榜的分数、调整、并列与参榜门槛；竞争排名出现1、1、3时，两个第1获得冠军徽章，第3获得季军徽章，不补造第2名。`badge_campaigns` 保存首次发放时间及排名依据，后续部署、重启、排名变化或公开设置变化不会重新授予名次徽章。

两枚参与纪念不受榜单公开设置限制，普通微信、开发及游客账号均可获得；排除旁观者、陪测账号、测试对局、管理员已排除或删除的记录。首次启动补发已有10月参与记录，后续归档对局或读取本人通知时补发新资格。按归档结束时间判定10月归属，不计入9月或11月对局。已有授予不会因后续更正或跨月收回。

`badge_awards` 对账号和徽章设置唯一约束，保证首次授予、补发及重试幂等，并保存发放时间、原名次和积分。永久徽章佩戴偏好使用 `period_start=0`，不随月榜重置；同月榜徽章共用最多3枚佩戴上限。读写版本会在新授予时更新，防止旧请求覆盖新状态。

通知接口：`GET /api/me/badges/notice` 合并本人所有未读徽章；`POST /api/me/badges/notice` 以 `through` 确认已展示的通知，不能确认别人的或未来的通知。客户端点击收下、查看收藏或主动关闭时确认；切后台、离开页面或临时断网不会丢通知。确认请求失败时只重试确认，避免重复弹窗。小程序在首页/我的安全空闲时提醒，网页版在首页/我的/徽章页提醒，其他面板、月初提醒和进行中牌局期间暂缓。

小程序和网页复用 `miniprogram/badge-awards.js` 的展示与通知逻辑、`badge-awards.wxss` 的视觉样式；小程序通过现有共享弹窗宿主显示，支持三枚、两枚和单枚布局及点击查看详情。活动图案使用用户已选定的原图裁切和透明外背景处理，没有重新绘制图案或签名。五枚缩略图和签名册高清图由服务端同源静态路径提供，避免增加小程序主包负担。

`node scripts/render-badge-awards-preview.js` 从正式WXML及共享展示逻辑生成三种领取情况与前三名的布局检查文件。发布顺序：部署通过CI的服务端镜像，启动即授予；再上传/发布小程序。老客户端不支持新弹窗时，徽章及未读通知仍持久保存，新客户端登录后显示。

## 月榜徽章

小程序和网页版共用 18 枚暗金纹章：`miniprogram/badges.js` 引用全部 15 个趣味称号，并增加积分榜「积分王者」、场次榜「牌桌常青树」、总胜率榜「常胜将军」。图案均为透明背景 PNG，沿用确认的古金浮雕与月桂边框，底部无宝石。源素材由内置 imagegen 制作，客户端使用 192px 压缩图。两端徽章页和预览画廊的总数从目录读取。

「金牌替身」对应既有 `good_shield` 指标，归好人趣味榜，按终局时存活的非梅林好人被最终刀选中的次数统计，包含派西维尔。使用现有历史投影，无需数据迁移。徽章同样由本月公开次数榜榜首持有，成功率榜不授予。图案以迎住刺客匕首的金色替身面具为中心，沿用古金边框、月桂和深蓝内底；不使用防御称号的盾牌。客户端资源为 `miniprogram/assets/badges/good_shield.png`，原图保存在 `output/imagegen/badges/good_shield.png`；制作记录见 [金牌替身图案](good-shield-artwork.md)。

## 资格

只按北京时间**当前月**的公开榜计算。趣味徽章取跨玩法、未筛选角色的**次数榜**，不以比例榜授予。积分、场次、总胜率徽章取对应月榜，复用已有参榜门槛、积分调整及原始胜率／样本量排序；所有实际 rank=1 的玩家（包括分页之外的并列榜首）均持有。零数据、隐藏榜单的玩家、游客、陪测账号不获授；开发账号沿用正常参榜资格。

资格按请求动态读取，复用榜单快照与提交后失效机制。榜首变化、公开开关变化、管理员更正或排除记录立即影响后续请求；跨月切换快照。没有历史数据删除、月末永久授予或定时清库。

## 佩戴与展示

佩戴区默认只展示三枚徽章，点击「管理」后显示逐枚摘下按钮，点击「完成」恢复紧凑展示。徽章详情使用内容自适应的底部面板，展示图案、月份、佩戴状态、获取条件及简要持有规则；完整计算规则由页面右上角「规则」入口查看。

获得本月资格时默认佩戴最多3枚，手动选择优先于新增徽章；「我的 → 荣誉徽章」位于「趣味记录」下方，点击进入独立页面（小程序 `/pages/badges/badges`，网页 `#/badges`）。顶部展示本月拥有数量和三个佩戴槽位，下方提供全部／已拥有／未拥有筛选；未拥有徽章以灰色图案、锁标记和获取条件展示。点击徽章查看详情，已拥有的徽章可逐枚摘下或重新佩戴；达到3枚时需先摘下再换装，服务端同步校验上限。偏好以玩家、徽章和月份存储，同月失去后重新取得资格时保留用户选择；新月重新默认佩戴最多3枚。修改仅限本人当前持有的徽章，采用版本和月份校验，并使用幂等回执处理重试。

房间、排行榜和月报入口共用玩家战绩卡。头像／昵称右侧仅显示已佩戴徽章图案，最多显示3枚；点击徽章只展开称号和介绍。关闭卡片、切换玩家或离开页面清空详情，迟到响应不能覆盖新玩家。

接口：`GET /api/me/badges` 返回本人当前持有徽章和佩戴状态；`POST /api/me/badges` 接收 `id`、`equipped`、`version`、`periodStart` 和 `Idempotency-Key`。战绩卡接口的 `player.badges` 只返回已佩戴徽章，不暴露账户标识、隐藏偏好或历史记录。

## 验证

`tests/badges.test.js` 覆盖月界、并列超过100名、总榜隔离、次数／比例差异、无记录、胜率规则、排名更新、公开开关、佩戴持久化、冲突与幂等、权限和卡片数据。`tests/web-client.test.js` 验证按需详情和佩戴交互。完整回归与小程序模板／主包检查沿用项目测试。

`node scripts/render-badges-preview.js` 从真实小程序模板生成战绩卡、长昵称、多徽章与详情预览，输出至 `output/playwright/badges/`。
